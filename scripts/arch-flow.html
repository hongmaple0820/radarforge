「AI 资讯雷达」系统架构与数据流
Next.js 16 App Router · 服务端 Key 代理 · 元宝搜索 SearchPro · LLM 早报汇总
阶段一 · 浏览器端（React 客户端组件） Frontend
1话题栏：选择 / 新增 / 删除追踪话题GET/POST/DELETE /api/topics
2控制面板：设置 Freshness（时效）· Mode（信源模式）· Industry（垂直领域）· Cnt（条数）
3话题或参数变化自动触发检索POST /api/search（Key 不进前端）
↓ JSON 请求体
阶段二 · 服务端代理层（Next.js Route Handler） API Layer
4入参校验：query 非空 · 长度 ≤ 500 字符 · 参数取值范围检查
5双模式路由：已配置 WSA_API_KEY → 真实调用；未配置 → 高保真演示数据（UI 明确标识）
6错误码映射：UnauthorizedOperation → 401 · ResourceNotFound → 403 · 15s 超时中断
↓ Bearer 鉴权 + JSON 入参
阶段三 · 腾讯云元宝搜索 SearchPro Yuanbao Search
7检索请求：POST api.wsa.cloud.tencent.com/SearchPro
8返回 Pages：JSON 字符串数组，逐条二次解析出标题 / 摘要 / 信源 / 时间 / 相关度
9携带 RequestId · Version · 端到端耗时回传前端展示
↓ 结构化结果 + 资讯卡片
阶段四 · 呈现与增值 Output
10资讯卡片流：按相关度 / 时间排序，favicon 加载失败自动回退字母头像
11信源统计面板：结果条数 · 平均相关度 · 站点分布 · RequestId
12AI 早报：POST /api/briefing，LLM 按 [n] 信源编号汇总当期资讯
数据持久化：Prisma ORM + SQLite（话题表）｜早报生成：z-ai-web-dev-sdk（仅服务端）｜演示模式与真实调用共用同一数据结构
