# Domain Docs（领域文档消费规则）

探索代码库之前，工程技能应如何消费本仓的领域文档。

## 探索前先读

1. **`GLOSSARY.md`**（仓库根）：双语词汇表——中文说法 ↔ 代码标识符一查即中
2. **`docs/adr/`**：读与即将改动区域相关的 ADR（如动视频提交链前先读 ADR-0006）

任何文件不存在时**静默继续**：不标记缺失、不建议先建。domain-modeling 纪律在术语或决策真正被解决时才惰性创建它们。

## 文件结构（单语境）

```
/
├── AGENTS.md          ← 约定与铁律（任何会话先读）
├── GLOSSARY.md        ← 双语词汇表（本文件消费规则的主体）
├── docs/
│   ├── adr/           ← 架构决策记录（追溯 7 篇起，增量常态补）
│   └── agents/        ← tracker/标签/标准/模板约定
└── src/
```

## 用词汇表的话说话

产出物（票标题、重构提案、假设、测试名）命名领域概念时，**用 GLOSSARY.md 定义的词**，不漂移到同义词。例：说「首帧」不说「第一张图」；说「分镜」不说「片段」；写代码注释引用概念时用英文标识符（keyframe、storyboard、lengthTier）。

需要的概念不在词汇表里，这是一个信号：要么你在发明项目不用的语言（重新考虑），要么存在真实缺口（记下来，走 domain-modeling 补词条）。

## 冲突要显式报

产出与既有 ADR 矛盾时，显式指出而不是静默覆盖：

> 与 ADR-0006（i2v 换号重试与槽位释放）冲突，但值得重开，理由是……

## 双语约定

- 中文文档里首次出现术语时可带英文括注（如「首帧（keyframe）」），此后用中文
- 代码/日志/JSON 字段一律英文；跨语言对齐以 GLOSSARY 表为准
