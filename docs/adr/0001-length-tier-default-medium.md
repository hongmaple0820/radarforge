# 0001 — 篇幅三档制，默认 medium

> 状态：已接受（用户拍板 2026-11-05，内容质量方案决策①）
> 溯源：commit `4825f55`（A2 落地）；`src/lib/runtime/length-tier.ts`；`docs/content-quality-upgrade-plan.md` 第八章

## 背景

升级前字数被四处旧硬钳直接钳死（顶格常量），既没有「用户选篇幅」的入口，也没有逐节预算带的概念：短文被撑水、长文被截断，字数落带率无从谈起。要引入档位制，必须先定默认档：medium（2500~4000，质量/成本平衡）还是 deep（4500~8000，封面级但单日产能掉到 5~8 篇）。

## 决策

- 三档 `LengthTierId = "short" | "medium" | "deep"`：快讯 1200~2000 / 标准深度 2500~4000 / 封面级长文 4500~8000
- **默认 medium**；非法/缺失回退 medium（与设置默认一致）
- 四处旧硬钳全改档位驱动；`AgentRun.lengthTier` 字段 + 入口校验 + 向导三卡 + 设置中心文章产线卡
- 逐节 ±65/±160 容差 + 滚动窗 + `inBand` 诚实留痕；合计预算带归一化

## 实证

落地当轮聚焦 E2E：默认 medium 成稿 2257 字带外触发逐节重生 → 2719 字落带；后续批次实测低于下限触发合法扩写（禁注水）后 3901 字落带。

## 后果与不变量

- 产能与质量的默认平衡点有了明确锚；deep 档留给封面级选题显式选择
- 任何新写入环节必须经档位预算带，不允许再出现硬编码字数钳（发现即违反本 ADR）
