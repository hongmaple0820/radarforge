# 0005 — 内容质量升级批次顺序：文章 → 配图 → 视频

> 状态：已接受（用户拍板 2026-11-05，内容质量方案决策⑤）
> 溯源：`docs/content-quality-upgrade-plan.md`（commit `4c0d0c4`）三批排期；落地批次 4825f55 → 80d8fe0 → 视频线 C1~C6

## 背景

三线都要改（A 文章 / B 配图 / C 视频），排期有两种：按「文章→配图→视频」推进（批次一最快见效），或视频优先。三线不是独立孤岛：A 线的 SKILL.md 接管（A1）、篇幅档（A2）是 B/C 线的提示词与预算地基；B 线的导演提示词工程（B1）与 VLM 审图（B3）被 C 线首帧直接复用。

## 决策

按依赖方向推进：**文章（批次一 A1/A2/B1/B3）→ 配图（批次二 B4/B2/B6/A3/A5/B5/A4）→ 视频（批次三 C1~C6）**。

## 后果（实证复盘）

- 批次二的三通道回退链（B5）直接救了视频线的首帧（生图失败不整线回退，i2v 用 code-card 兜底首帧照常生成）
- 批次三的 i2v 验收站在 A/B 两批地基上，只暴露外部容量约束（队列时段），零代码返工
- 若当时视频优先：首帧导演、审帧、预算带都要在视频线里临时发明，再回头改文章线——返工路径

## 不变量

未来大升级排期默认按「被依赖方先行」拆批；跨线复用的能力（导演、审帧、回退链）先落在先决批次。
